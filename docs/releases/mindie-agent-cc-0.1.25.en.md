# mindie-agent-cc 0.1.25: Storage lifecycle governance and silent legacy reclamation

[中文](mindie-agent-cc-0.1.25.md)

- **Formal component pins**: the runtime components now point at reviewed immutable commits — `mindie-knowledge v0.13.22` (`c991b64`), `mindie-diagnostics v0.5.14` (`cd16baa`), `remote-dev v0.11.12` (`c4d38f9`), `mindie-coordinator v0.7.11` (`33e2c69`), `mindie-profiler v0.5.14` (`889b6ef`), `mindie-sim v0.9.15` (`9dbab02`), and `mindie-debugger v0.1.3` (`33052a2`). `uv.lock` and `[tool.uv] override-dependencies` carry the same pins, removing floating references.
- **One runtime build per plugin upgrade**: when a component floor is already installed, `bootstrap.py` calls the new `component_update.py` with the existing interpreter and reuses the merged runtime directly. A baseline is built only when no component override is needed or the existing interpreter is unusable, eliminating the duplicate baseline plus merged `.venv`. When uv's default cache crosses a volume (including Windows drive boundaries), `uv sync` uses the same-volume `runtimes/cc/.uv-cache`, restoring `clonefile`/hardlink behavior.
- **Hidden launch root follows the switch**: after a component update or activation changes `cc.json["python"]`, `$CLAUDE_PLUGIN_DATA/releases/<active>/entry.py` is atomically rebound to the new interpreter. Superseded `releases/<old>` directories are retired with a bounded policy that keeps the current version and one rollback generation and never removes a live-referenced root.
- **Resident MCP holds a shared runtime lease**: `native_mcp.serve()` and the standalone resident `mcp_server.serve()` hold `acquire_runtime_lease` on `owning_dir(sys.executable)` and the bound runtime directory. The kernel releases the lease on exit or crash, so reclamation cannot retire a generation in use.
- **Automatic legacy and session reclamation**: after a switch, during the background release-check cycle, from the slash-command entry, and before a build, bounded calls to `sweep_legacy_installations` / `prune_component_runtimes` silently reclaim `runtimes/cc/*`, `adapter-state/installations/*`, and `adapter-state/component-runtimes/*`. Terminal `mcp-binds.sqlite3` rows older than seven days and dead `remote/<session>` roots with no live process or lock are pruned under WAL plus `busy_timeout`. `bound`/`claimed` binds and any unresolved remote write state (`submission_state=uncertain|unknown`) are never touched.
- **Cross-platform deletion discipline**: every directory retirement goes through `mindie_knowledge.storage.retire_directory`. POSIX locks stay inside the target; Windows never holds a handle inside a directory it renames. An NTFS `PermissionError` becomes `deferred_in_use` with the source tree preserved, never a half-deleted retry. New Windows builds use a 24-character short key while existing 64-character directories and their `.ready.json` remain readable.
- **Honest status**: after a successful main path, busy or budget-exhausted cleanup only adds `cleanup_warning` / `deferred_in_use`; it never changes a tool result, activation status or installation status, and never writes a one-way `fault`.
- **sim output budget**: the new `mindie-sim` SLA frontier is about 220 KiB of structured output, so the `components` sim default output budget is raised to 512 KiB. Every component remains capped at 1 MiB, and official CLI calls that omit an explicit budget are no longer truncated.

Design note: shared storage lifecycle policy lives in `mindie_knowledge.storage` from `mindie-knowledge v0.13.22`; this release only wires the Claude Code launch root, leases and session state into it.
