# mindie-agent-cc 0.1.32: 9-Domain Knowledge Bindings, Disjoint MCP Surfaces, and Cold-Start / Revocation Hardening

[中文](mindie-agent-cc-0.1.32.md)

- **Complete 9-package runtime lock and 9-domain content-addressed knowledge bindings**: Declares and pins all 9 runtime packages across [`pyproject.toml`](../../pyproject.toml), [`uv.lock`](../../uv.lock), and [`product-contract.json`](../../product-contract.json) (adding `npu-top 0.3.5` alongside `mindie-harness 0.1.5`, `mindie-knowledge 0.13.25`, `remote-dev 0.11.15`, `mindie-diagnostics 0.5.17`, `mindie-coordinator 0.7.14`, `mindie-debugger 0.1.4`, `mindie-profiler 0.5.16`, and `mindie-sim 0.9.18`, compatible with `mindie-harness >= 0.1.5`). Both `entry.py:initialize_profile` and `setup.py:initialize_profile` invoke `ensure_knowledge_binding(..., already_locked=True)` inside one `.cc.json.update.lock` transaction to provision content-addressed `engines/cc/<20hex>/<domain>.engine.json` files for all 9 domains while keeping `vllm-ascend.engine.json` as the canonical `engine_config` and preserving `cc.json` untouched on `deferred` outcomes. `host_adapter.py:adapter_plugin_root` resolves `scripts/transcript.py` across both source checkouts and installed wheel (`mindie_cc`) layouts without falling back to a no-op adapter.
- **Strictly disjoint MCP surfaces with positive `tools/call` verification**: `ManagedMCPAdapter("cc")` keeps all three MCP servers strictly separated—`knowledge` exposes only the 5 `knowledge_*` tools (`knowledge_query`, `knowledge_explain`, `knowledge_feedback`, `knowledge_distill`, `knowledge_sync`), `components` exposes the 11 local and component tools (`mindie_status`, `mindie_doctor`, `diagnostics_status`, `diagnostics_bundle`, `profiler`, `sim`, `coordinator`, `npu_top`, `debugger`, `rsi_loop`, `experiment_ledger`) with zero `knowledge_*` or `remote_*` overlap, and `remote` exposes the 13 `claude` profile tools (`remote_BashOutput` and `remote_KillShell` excluded). Cross-surface calls fail closed with `unknown_operation`, and read-only calls never create `admission.sqlite3`.
- **Sub-30ms marker-only cold `SessionStart`, `stdin=DEVNULL` seed bootstrap, and `Stop` revocation permanence**: Cold `SessionStart` (`session_start.py` -> `mindie_launch.py`) stays pure-stdlib and marker-only—atomically writing `pending-update-check.json` and returning `{}` in `< 30ms` with zero `uv sync`, zero runtime builds, and zero SQLite files. Cold seed bootstrap (`mindie_launch.py:_cold`) isolates `stdin=subprocess.DEVNULL` and `stdout=sys.stderr` so MCP JSON-RPC streams stay intact, rejects `WindowsApps` / 0-byte Python stubs, and exits non-zero if no valid runtime interpreter is available after bootstrap. `entry.py:_stop` checks `Admission.inspect(session)` before capture so explicitly revoked (`status == "inactive"`) sessions exit immediately and are never revived by `run_stop_capture(..., timeout_sec=6.0)`.
- **Lean script budget and CI host acceptance (`verify-host-plugin.yml`)**: Keeps `scripts/*.py` at `1,344` total lines across the 8 core modules and 4 `v0.1.29` live self-upgrade shims (`<= 1,350` target / `<= 1,500` ceiling), expands contract tests for positive MCP tool execution, wheel-layout `transcript.py` resolution, single-lock `deferred` safety, and `Stop` revocation permanence, and wires `mindie-agent/mindie-bench/.github/workflows/verify-host-plugin.yml@main` (`host: cc`) into `.github/workflows/checks.yml`.
