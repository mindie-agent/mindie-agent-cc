# mindie-agent-cc 0.1.32：9 领域知识绑定、MCP 工具面严格隔离与冷启动 / 撤权收敛加固

[English](mindie-agent-cc-0.1.32.en.md)

- **补齐 9 大运行时组件锁定与 9 领域内容寻址知识绑定**：在 [`pyproject.toml`](../../pyproject.toml)、[`uv.lock`](../../uv.lock) 与 [`product-contract.json`](../../product-contract.json) 中完整声明并锁定全部 9 个运行时组件（新增 `npu-top 0.3.5`，同步 `mindie-harness 0.1.8`、`mindie-knowledge 0.13.25`、`remote-dev 0.11.15`、`mindie-diagnostics 0.5.17`、`mindie-coordinator 0.7.14`、`mindie-debugger 0.1.4`、`mindie-profiler 0.5.16`、`mindie-sim 0.9.18`，兼容 `mindie-harness >= 0.1.5`）。`entry.py:initialize_profile` 与 `setup.py:initialize_profile` 在单一 `.cc.json.update.lock` 排他锁事务内调用 `ensure_knowledge_binding(..., already_locked=True)`，一次性生成内容寻址的 `engines/cc/<20hex>/<domain>.engine.json` 9 领域配置（默认 `engine_config` 保持指向 `vllm-ascend.engine.json`，遇 `deferred` 状态时不覆盖既有 `cc.json`）；`host_adapter.py:adapter_plugin_root` 同时兼容源码检出与 Wheel 安装（`mindie_cc`）布局下的 `scripts/transcript.py` 解析，避免退化为空采集回退。
- **三套 MCP 服务严格正交隔离与端到端正向调用契约**：通过 `ManagedMCPAdapter("cc")` 保持三套 MCP 服务互不重叠——`knowledge` 仅暴露 5 个 `knowledge_*` 工具（`knowledge_query`、`knowledge_explain`、`knowledge_feedback`、`knowledge_distill`、`knowledge_sync`）；`components` 暴露 `mindie_status`、`mindie_doctor`、`diagnostics_status`、`diagnostics_bundle`、`profiler`、`sim`、`coordinator`、`npu_top`、`debugger`、`rsi_loop`、`experiment_ledger` 共 11 个本地与组件工具（零 `knowledge_*` / `remote_*` 混入）；`remote` 仅暴露 13 个 `claude` 规范工具（剔除 `remote_BashOutput` / `remote_KillShell`）。跨工具面误调一律以 `unknown_operation` 显式拒绝，只读工具调用全程零 `admission.sqlite3` 创建。
- **`< 30ms` 纯标记冷启动、`stdin=DEVNULL` 种子引导与 `Stop` 撤权永久性保障**：冷态 `SessionStart`（`session_start.py` -> `mindie_launch.py`）保持纯标准库标记写入（原子生成 `pending-update-check.json` 并在 `< 30ms` 内返回 `{}`，零 `uv sync`、零运行时构建、零 SQLite）；冷启动种子引导（`mindie_launch.py:_cold`）使用 `stdin=subprocess.DEVNULL` 与 `stdout=sys.stderr` 隔离 MCP stdio 流，过滤 Windows Store `WindowsApps` 空字节解释器别名，并在引导后仍无有效运行时解释器时显式非零退出；`entry.py:_stop` 在校验 `sharing_status` 与授权 `project_roots` 后优先核查 `Admission` 状态，对已显式停用（`status == "inactive"`）的会话直接短路退出并通过 `run_stop_capture(..., timeout_sec=6.0)` 保证撤权状态永不被后续回合复活。
- **精简脚本预算与宿主验收门禁（`verify-host-plugin.yml`）**：`scripts/*.py`（8 个核心模块 + 4 个 `v0.1.29` 在线平滑升级兼容桩）总计压缩至 `1,344` 行（满足 `<= 1,350` 目标与 `<= 1,500` 硬上限）；补齐三套 MCP 正向 `tools/call` 调度、Wheel 布局 `transcript.py` 解析、单锁 `deferred` 保护与 `Stop` 撤权永久性单测，并在 `.github/workflows/checks.yml` 接入共享 `verify-host-plugin.yml`（`host: cc`）原生宿主验收任务。
