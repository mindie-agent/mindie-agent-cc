# 服务连续性与平滑更新

<b>中文</b> | <a href="service-continuity.md">English</a> · <a href="README.md">返回文档索引</a>

`mindie-agent-cc` 采用 Claude Code 原生插件市场机制与不可变的 `uv` Python 运行时。全系统仅通过单一的适配器配置文件记录当前生效的安装绑定，并由共享的 `mindie-knowledge` 核心统一管理后台知识服务的身份与进程生命周期。

---

## 1. 不可变运行时准备与并发锁控制

### 在途业务外的隔离构建
- **首次安装初始化**：在校验持久化存储格式无误后初始化适配器配置。
- **后台候选版本与组件构建**：当检测到兼容的新插件 Release 或共享组件正式 Release（直接从各官方组件仓库发现并继承已安装组件版本下界）时，系统在操作锁之外通过 `uv` 独立构建不可变的候选运行时，并通过隔离包清单核验与无模型 API 探针完成校验；构建与校验过程绝不打开或修改正在使用的数据库，也不主动拉起知识后台服务。
- **日常请求使用共享锁**：常规 MCP 工具调用、只读状态查询（`status`）与本地取消操作均通过共享锁读取当前完整的运行时绑定；长耗时任务不会阻塞其自身的状态查询或取消信号。

### 空闲时原子切换（Idle Cutover）
- **仅在空闲时获取排他锁**：切换到新版本运行时需要获取排他锁，但绝不会强杀正在执行的业务操作。若后台核心正忙，切换会自动推迟到当前操作完成后进行。
- **有序服务交接**：确认空闲后，先安全退役旧服务实例，随后冷态原子更新安装绑定配置（默认 `~/.config/mindie-agent/cc.json`），知识后台服务仅在后续已授权的手动知识操作中按需拉起。
- **观察窗口绝不误杀任务**：30 秒的控制面观察窗口仅用于限制等待空闲的时间，超时绝不会终止正在运行的业务任务，也不会伪造成功回执。
- **常驻 MCP 进程平滑过渡**：已启动的 MCP stdio 进程在更新后无需重启会话，下一次工具调用会自动按最新提交的运行时绑定分派执行。

## 2. `Stop` 采集队列可靠性与用户配置持久化

### 更新期间的 `Stop` 事件保障
- `Stop` Hook 直接读取一次不可变的绑定快照并将采集引用写入持久化 SQLite 队列，无需等待后台服务准入。
- 即使旧版辅助脚本在更新切换瞬间刚被退役，它依然可以将已授权的 `Stop` 事件安全写入同一个持久队列（而不会重新拉起旧服务）；新服务实例接管后会继续消费该队列并按原生事件 ID 自动去重。
- 若采集阶段发生已知错误，仅在终端输出一条静态告警，绝不诱导业务大模型继续续跑。

### 用户授权与代码版本解耦
- 社区知识贡献与自动工具故障上报共用 `<profile>/.mindie/mindie-consent.json` 中的单一统一贡献开关，与已批准的项目路径范围一起作为持久化用户数据独立保存。
- 插件版本更新或宿主重载绝不会重新弹窗索要授权、重置项目范围、修改已保存的 `disabled` / `later` / `read-only` 选项，也不会将缺少统一授权版本的旧版 `contribute` 记录（`needs_choice`）自动扩大为故障上报授权。

---

## 3. 隔离的整理模型调用与服务复用

- **严格的配置指纹校验**：复用后台知识服务要求引擎配置指纹、当前安装绑定与 Worker 健康状态完全一致。仅端口可达但属于旧版本的服务端点不会被误用；当核心报告服务状态未知或异常时，适配层绝不私自拉起第二个竞争 Worker。
- **纯净隔离的整理进程**：在调用原生 Claude CLI 生成分块检索导航元数据时，Worker 仅从所选配置中提取受支持的 Provider、Model 与 Effort 参数注入隔离环境，不加载用户的 Hook、MCP 服务、自定义工具或项目级指令，且绝不将密钥写入状态回执。

---

## 4. 验证范围说明

- **守护进程与实机验收**：已覆盖 macOS（`2.1.269`）、原生 Windows 与 WSL（`2.1.299`）下的活跃服务切换、无服务启动、撤权与回滚路径，确认在途任务租约在更新后完整保留，且停用后所有归属子进程均被干净回收。
