# 故障诊断与本地取消

[English](failure-diagnostics.md) | 中文

原生 `status` 命令报告当前的知识配置、服务与存储健康状况、当前任务的绑定状态与诊断失败计数，以及与已绑定任务关联的最近 5 次采集和贡献批次。当缺少任务身份时不会返回任何任务记录。短暂的本地或网络故障由既有后台 Worker 自动恢复，`status` 是观察该问题状态的只读入口。失败的批次 ID 可通过可选的 `recover` 命令检查；当外部发布结果处于未知状态时，必须在任何显式重试前先完成对账。

`status` 不会初始化数据库、启动模型或后台服务、绑定任务、重置失败计数，也不会重放已消费的输入。SQLite 只读访问可能会创建正常的 WAL 读取附属文件，但不会修改任何业务记录。故障投影会剔除原始模型提供商标准错误输出（stderr）、对话正文、Token 凭证以及其他任务身份信息。若已有适配器配置文件损坏，将直接报告诊断错误，而绝不会当作“首次使用”重新引导。当知识服务不可用时，原生 Shell/SSH 以及独立的 `remote-dev` 仍保持正常可用。

在有界工具请求运行期间，stdio 前端保持输入响应。取消（Cancel）与 EOF 仅清理当前归属的本地子进程；取消本地观察并不代表远端作业已经终止。响应结果会保留原始远端作业引用与投递确定性状态。在提交新作业前，请显式检查或停止该远端作业。远端轮询单次等待上限为 30 秒，且不会改变远端工作负载本身的超时设置。

macOS 实机验证覆盖了任务隔离的 SQLite 诊断、计数不变的暂停状态、损坏配置识别、子进程/孙进程取消清理、繁忙期间 ping 响应、EOF 处理、输出背压、更新锁取消以及安全的远端异常分类。开发契约测试持续保护这些边界。受控的原生身份与 helper 接缝测试不替代宿主 UI 取消事件触发、远端作业停止或完整贡献闭环的实机证据。

Windows 实机管道写入阻塞与进程树清理行为仍需独立实机验收。上述机制不引入新的自动重试或额外后台常驻服务。

## 自动产品故障上报

本适配器复用共享的 `mindie-diagnostics` 上报组件。经确认的产品自身故障会生成有界的本地诊断记录；在用户独立保存上报授权并完成一次性 Reporter 准备后，后台 Worker 会在不调用模型、不打扰日常任务的情况下自动整理并提交脱敏的 GitHub Issue。普通的业务命令执行失败不会被自动判定为产品缺陷。

公开上报载荷仅包含允许的产品代码元数据，绝不包含任务文本、原始异常栈、凭证、命令、路径或本地事件 ID。重复故障共享同一指纹；当 Issue 创建结果不确定时，必须在任何后续动作前先完成对账，绝不盲目重复提交。日志记录或故障上报本身的失败不能覆盖或替代原始业务执行结果。

失败的原生摘要整理调用会在现有私有结果回执的 `raw_result` 字段中保留有界的 `mindie-cc-native-failure/1` 投影。该投影仅包含已知的原生子类型/终止枚举、经校验的轮次（turn）与 HTTP 状态码数值，以及错误或结果字段的结构/数量；绝不保留模型提供商或模型的自由文本、未知标签、会话 ID、提示词或凭证。未知的原生字段值会显式标记为 `unknown`。原始用量、计费状态与失败结论保持权威性，不会发起任何额外的模型调用。

原生轮次上限（turn-limit）、费用预算耗尽（cost-budget）与结构化输出重试耗尽（structured-output exhaustion）各自映射到独立的静态共享失败原因，使调用方摘要详情能够直接定位失败边界。枚举定义已在已安装的 Claude Code `2.1.269` 结果 Schema 与终止构造器中核对。对于原始信封已被丢弃的历史旧失败记录，不会逆向猜测其子类型。归属子进程清理完成后，仍须按契约删除临时 scratch 目录。

故障投影机制已对照全部九条设计原则完成审查（对应设计原则版本 `62cdd5ae40553df2f0f7f7d022141123792d2944`）：解决了此前无法在不再次付费调用模型的情况下诊断失败原因的问题（原则 1）；在既有回执与调用方失败契约内采用有限枚举投影（原则 2、4）；不增加配置项或用户工作流负担（原则 3、5、7）；不将摘要提升为权威证据或改变正文归属（原则 6）；复用既有账本、用量记账、scratch 属主与有效的历史原生读取结果（原则 8）；保留具体失败原因、已知用量、保密边界与禁止重放语义（原则 9）。合成测试覆盖了全部三类限制、不可信自由文本/类型以及终止事件后伴随非零退出的场景。原始已计费失败被完整保留，绝不自动重试。

启用故障上报（`reporting-enable`）会先保存显式用户偏好，再修改策略状态。若授权记录不可读或已损坏，实际策略保持不变。若策略状态与已保存的用户选择不一致，将显式暴露为 `consent_mismatch` 并附带真实的 `policy_enabled` 状态。已保存的选择不会在后续任务中重复询问。返回的初始化 `command` 为参数数组（argv），`command_line` 显式声明 `command_shell`，并在 Windows 下采用 PowerShell 引用规则。

合成适配器/日志/发件箱/模拟 Issue 检查与 Windows 进程身份检查记录于 `mindie-agent/diagnostics` 仓库中；这些组件检查不替代原生 Claude 事件投递、计划任务配置或真实公开 Issue 写入验收。
